# 라이브 시청 제한 — 15분 상한·5분 쉼·한 기기 (2026-09-30)

> 상태: 🟡 서버 PR #15 제출 · 앱 0.144.0+363 main 병합(09-30) · 서버 배포 대기 · 결정: owner 2026-09-29 · 근거: `specs/camera-reliability-2026-09.md` P4
> 서버: `backend/live_session.py` · 앱 전달: `docs/APP_LIVE_VIEW_LIMIT_2026-09-30.md`

## 왜
- 라이브를 오래 켜두면 카메라 WebRTC 루프가 고착돼 영상이 멈추고(stalled), 앱이 재연결을 반복하며 악화 →
  펌웨어 워치독 재부팅(`SW:rtc_loop_stall`). 09-29 현장 B: 3시간 연속 시청·재연결 248회 → 16:49 자가 재시작(이관훈 확인).
- 폰+시뮬레이터 동시 시청 때 카메라가 40초 먹통.
- 카메라의 본업은 녹화 → 라이브를 짧게 끊어 카메라를 보호한다.

## 결정 (owner 2026-09-29)
| 항목 | 결정 |
|---|---|
| 시청 상한 | 한 번에 **15분** |
| 상한 후 | **5분** 쉬어야 다시 시청 |
| 강제 위치 | **서버도 강제**(업데이트 안 한 앱도 적용) |
| 동시 시청 | **한 기기만**. 다른 기기면 "○○에서 시청 중입니다. 연결할까요?" → 예 = **가져오기**(저쪽 끊김) |
| ○○ 표시 | **기기 종류 + 모델** (예: "iPhone 15", "Galaxy S24") |

## 기본값 (구현 시 정함 — owner 확인 필요 시 변경 쉬움)
- **15분 시계는 카메라 기준 연속 시청 시간.** 같은 기기 재연결, 다른 기기 가져오기, 끊고 60초 안 재시작은 시계가 이어진다.
  기기별로 따로 세면 기기를 번갈아 가져오거나 껐다 켜서 카메라가 쉬지 않고 라이브할 수 있다(09-29 B 와 같은 구조).
- **구버전 앱**(viewer_id 안 보냄)은 한 기기 제한 없이 15분·5분만. 새 앱에는 "이전 버전 앱에서 시청 중"으로 보인다.
- 쉼은 **15분 상한으로 끝났을 때만**. 사용자가 직접 닫았거나 가져오기 당한 경우는 쉼 없음(단, 60초 안 재시작은 시계 이어짐).

## 체험 흐름 (유저 시점)
1. **[화면]** 라이브 탭 → **[서버]** 세션 시작, 응답 `live_until`(15분 뒤) → **[화면]** 영상 + (선택) 남은 시간.
2. **[15분]** 서버가 카메라 세션을 닫음 → cameras Realtime `live_end_reason='time_limit'` →
   **[화면]** "녹화 진행을 위해 카메라 라이브가 절전모드로 들어갑니다" + 5분 뒤 다시 보기(카운트다운). 자동 재연결 안 함.
3. **[5분 안에 다시 보기]** 서버 429 `live_cooldown` + `retry_after` → **[화면]** "n분 뒤 다시 볼 수 있어요".
4. **[폰 A 시청 중, 폰 B 라이브 탭]** 서버 409 `live_in_use`, `viewer="iPhone 15"` →
   **[폰 B]** "iPhone 15에서 시청 중입니다. 연결할까요?" [예/아니오].
5. **[폰 B '예']** `takeover=true` 로 다시 요청 → 서버가 A 세션을 카메라에서 닫고 B 연결 →
   **[폰 A]** Realtime `live_session_id` 가 남의 것 + `live_end_reason='taken_over'` → "Galaxy S24에서 시청을 시작해 라이브가 종료됐어요". **자동 재연결 안 함**(핑퐁 방지).
6. **[폰 B '아니오']** 아무 요청 안 함. A 계속 시청.

## 서버 구현
- `cameras` 컬럼 7개(`migrations/2026-09-30_cameras_live_session.sql`) + 기존 `stream_mode`/`stream_until`(= 시작 + 15분).
- `POST /cameras/{id}/webrtc/offer`: body `viewer_id`·`viewer_label`·`takeover` 추가. 카메라에 offer 보내기 전에 판정.
  - 409 `{code:'live_in_use', viewer, since}` · 429 `{code:'live_cooldown', retry_after}` + `Retry-After`
  - 429 `{code:'rate_limited', retry_after}` (시간당 안전망 #12, 이번에 code 추가)
  - 200 에 `live_until` 추가. 연결 실패(502/504)면 세션 기록 해제.
- `POST /webrtc/close`: **이 세션이 활성일 때만** 정리(가져오기 당한 기기의 늦은 close 가 새 시청자를 지우지 않게).
- API 프로세스 스레드 `LiveSessionReaper` 가 15초마다 만료 세션을 카메라에서 닫고 5분 쉼 기록.
- 단일 uvicorn 프로세스 전제(프로세스 락으로 판정·기록). 여러 프로세스로 늘리면 DB 조건부 UPDATE 로 바꿔야 함.
