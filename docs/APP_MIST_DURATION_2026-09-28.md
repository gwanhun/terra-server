# 앱 전달 — 분무 시간 자유 설정(1~20초) + 신 펌웨어는 분할 없이 한 번에

> **대상**: 앱 개발 담당
> **작성**: terra-server 백엔드 담당, 2026-09-28
> **성격**: 분무 `duration_ms` 의 **화이트리스트(1/2/3/5/7/10초)를 폐지**하고 1000~20000 범위의 정수면 받습니다. 같은 날 리플래시하는 펌웨어는 분무 상한이 30초로 올라 10초·20초 분무가 **분할 없이 한 번에** 나갑니다. **필수 작업은 없습니다.** 기존 5초·10초 칩은 그대로 유효하고, 20초 칩이나 슬라이더 추가는 선택입니다.
> **관련 커밋**: 서버 `7eb159d`·`e2eba29`(운영 배포 예정, §4) · 펌웨어 nano `a09772f` / supermini `7ed013d`. 배경 문서: [BACKEND_HANDOFF_REPLY_MIST_DURATION_2026-09-23.md](BACKEND_HANDOFF_REPLY_MIST_DURATION_2026-09-23.md)

## 1. `duration_ms` 검증 — 화이트리스트 → 범위

| | 9/23 ~ 9/28 | 9/28 배포 후 |
|---|---|---|
| 허용값 | 1000 / 2000 / 3000 / 5000 / 7000 / 10000 | **1000 ≤ 정수 ≤ 20000** (예: 4000, 13500 도 OK) |
| 거절(400) | 목록 밖 전부 | 범위 밖(500, 25000 …) 또는 정수 아님 |
| 적용 경로 | REST `POST /devices/{id}/mist`, 예약 `POST /schedules` | 동일 (두 경로가 같은 검증 함수) |
| `commands` 직접 INSERT | 서버 검증 없음(RLS 만) | 동일 |

- 20000 은 **서버 정책 상한**입니다. 펌웨어 하드 상한(30000)과 별개라, 나중에 서버 값만 올리면 앱은 그대로 됩니다.
- 기존 칩(5초·10초)은 범위 안이라 아무 변화 없습니다. 옛 예약(1/2/3/7초)도 그대로 발화합니다.
- 슬라이더를 넣는다면 1~20초, 1초 단위를 권장합니다. 밀리초 단위 값도 받지만 의미가 없습니다.

## 2. 기기별 동작 — 신/구 펌웨어

서버는 기기가 보고한 상한(`capabilities.mist_max_ms`, 미보고 = 5000)을 넘는 요청을 **5초 단위로 나눠** 보냅니다. 앱은 기기 구분 없이 값만 보내면 됩니다.

| 요청 | 신 펌웨어 (`mist_max_ms` 30000, 9/28 리플래시) | 구 펌웨어 (미보고 = 5000) |
|---|---|---|
| 5초 | 한 번에 | 한 번에 |
| 10초 | **한 번에 10초**, `commands` 1행 | 5 + 5. 원 명령 1행 + `source='timer'` 후속 1행, 총 ~12초 |
| 13초 | **한 번에 13초**, 1행 | 5 + 5 + 3. 후속 2행, 총 ~17초 |
| 20초 | **한 번에 20초**, 1행 | 5 × 4. 후속 3행, 총 ~26초 |

- 후속 행은 `action=mist`, `source='timer'`, `reason="mist split of <원 명령 id> (+Nms)"`, 원 명령과 같은 `issued_by`. 발행될 때마다 나머지를 다시 나눕니다(15000 → 5000 발행 + 10000 후속 …).
- 원 명령은 첫 분사 ack 로 `acked`/`ok`. 후속은 각자 ack. 푸시는 `source='schedule'` 만 나가므로 후속은 알림 없음.
- **구 펌웨어도 안전합니다.** 분사마다 펌웨어 타이머가 끄므로 후속이 유실돼도 물이 덜 나올 뿐 펌프가 켜진 채 남지 않습니다. 펌웨어에 5초 넘는 값이 직접 닿아도 5초로 자릅니다.
- 어느 기기가 신 펌웨어인지는 `devices.sys_state != null` 로 알 수 있습니다([APP_DEVICE_REBOOT_SYS_STATE_2026-09-28.md](APP_DEVICE_REBOOT_SYS_STATE_2026-09-28.md) §3). 다만 분무에는 그 구분이 필요 없습니다.

## 3. UX 권장

- **버튼 잠금**: 총 분사 시간 + 3초 (9/23 규칙 그대로). 구 펌웨어는 분할 사이 쉼 때문에 실제로는 조금 더 걸리지만, 잠금 중 재요청은 펌웨어가 `busy` 로 거절하므로 문제 없습니다.
- **명령 이력**: 후속 `timer` 행을 "2회 분사"처럼 표시하는 로직이 있다면 신 펌웨어에서는 1행만 오는 것이 정상입니다.
- **예약**: 10초·20초 예약도 발화 시 같은 규칙입니다. 앱 변경 없음.
