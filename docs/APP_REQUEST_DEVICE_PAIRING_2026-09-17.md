# 앱 요청 — 기기 등록·삭제·재등록 계약 정리 (2026-09-17)

> **수신**: 앱(Flutter) 담당 · **발신**: 펌웨어/서버 담당
> **배경**: 앱에서 사육장 기기를 BLE로 등록하면 와이파이는 붙는데(`WIFI_OK`) 서버에 기기가 생기지 않음. 서버 기록상 9/7 이후 신규 등록 0건.
> **원인 요약**: 펌웨어를 대조해 보니 **앱 문서에 적힌 계약과 실제 펌웨어가 다릅니다.** 등록 결과 알림(`PAIR_OK`)이 펌웨어에 없고, 한 번 등록된 기기는 재등록되지 않으며, 카메라는 앱 등록 경로 자체가 없습니다. 앱 잘못이 아닐 가능성이 큽니다.
> **부탁**: §1 확인 5건 답변. §2 는 이쪽 펌웨어 작업이고, 그중 앱이 맞춰줄 것은 **`UNPAIR` 한 줄**(§2-2)뿐입니다.
>
> **2026-09-17 저녁 갱신**: §2 펌웨어 4항목을 **사육장 기기·카메라 양쪽에 구현 완료**(빌드 통과, 실기 검증·배포 전). 최종 명령·알림 표는 §5. 기기에 새 펌웨어가 올라간 뒤부터 §5 시퀀스로 등록하면 되고, 그전까지는 §3 우회.

## 0. 지금 실제로 되는 것 / 안 되는 것

| 기능 | 사육장 기기 | 카메라 | 비고 |
|---|---|---|---|
| 앱에서 **등록** | △ 되지만 성공·실패를 앱이 알 수 없음 | ✕ 불가 | 카메라는 플래시 시 개발 계정으로 자동 등록됨 |
| **세트에 할당** | ✅ `PATCH /devices/{id} {"enclosure_id"}` | ✅ `PATCH /cameras/{id} {"enclosure_id"}` | 등록 요청엔 그룹 id 가 없어 등록 뒤 이 호출이 필요 |
| **삭제** | ✅ `POST /devices/{id}/unlink` (소프트, 기록 보존) / `DELETE` (완전) | ✅ 동일 | 서버에서만 지워지고 **기기는 모름** |
| **삭제 후 재등록** | ✕ 기기가 저장된 자격증명으로 등록을 건너뜀 | ✕ 동일 | 펌웨어 `UNPAIR` 필요(§2-2) |

## 1. 앱 팀 확인 요청 (5건)

| # | 확인 사항 | 이유 |
|---|---|---|
| 1 | `WIFI_OK` 이후 **무엇을 기다리는지** | 펌웨어는 `PAIR_OK` 를 보내지 않습니다. 이걸 기다리면 성공해도 앱은 영원히 대기로 보입니다 |
| 2 | BLE 전송 순서와 기기 알림 로그 한 벌 | 필수 순서 `SSID:` → `PASS:` → **`NAME:`** → `JWT_BEGIN <길이>` → `JWT:<청크 ≤200자>`×N(50ms 간격) → `CONNECT`. 알림 `NAME_OK` `JWT_BEGIN_OK` `JWT_OK <길이>` `WIFI_OK` 가 전부 찍혔는지. **`NAME:` 이 없으면 펌웨어가 조용히 등록을 건너뜁니다** |
| 3 | JWT 가 **현재 세션 access_token** 이고 등록 직전에 갱신하는지 | 만료면 서버 401. 앱엔 알림이 없음 |
| 4 | 테스트 기기가 **이전에 등록된 적 있는 기기**인지 | 저장된 자격증명이 있으면 등록을 건너뜁니다(§0 마지막 줄) |
| 5 | 등록 후 `PATCH /devices/{id}` 로 그룹 배정을 하고 있는지 | 이 호출이 없으면 세트에 안 들어갑니다 |

예상 원인 순위: ④ 이미 등록된 기기 > ① `PAIR_OK` 대기 > ② NAME 누락/JWT 불완전 > ③ JWT 만료.

## 2. 펌웨어 보완 (이쪽 작업 — 사육장·카메라 공통 프로토콜)

| # | 내용 | 앱이 할 일 |
|---|---|---|
| 1 | `PAIR_OK <device_id>` / `PAIR_FAIL <사유>` BLE 알림 추가 (사유: `401`, `timeout`, `no_name`, `server_5xx`) | 완료 후 이 알림으로 등록 결과 판정. 그전엔 §3 방식 |
| 2 | `UNPAIR` BLE 명령 추가: 저장된 자격증명 삭제 → `UNPAIR_OK` 응답 → 다음 `CONNECT` 에서 새로 등록 | **등록 시퀀스 맨 앞(`SSID:` 전)에 `UNPAIR` 를 항상 먼저 전송.** 처음 등록하는 기기엔 무해하고, 삭제된 기기·다른 계정 기기 모두 그 자리에서 재등록됨. 삭제 화면은 손댈 필요 없음 |
| 3 | 카메라 BLE에 `NAME:` `JWT_BEGIN` `JWT:` 수신 추가, 사용자 JWT 로 등록 | 카메라도 사육장 기기와 **같은 시퀀스**로 등록 가능해짐. 개발 토큰은 폴백으로만 |
| 4 | (선택) `ENC:<enclosure_id>`: 등록 시 그룹 즉시 배정 | 원하면 등록 시퀀스에 추가. 없으면 지금처럼 PATCH |

**→ 2026-09-17 구현 완료.** 전체 표는 §5.

## 3. 그전까지의 우회

- 등록 성공 판정: `WIFI_OK` 뒤 10초쯤 `GET /devices` 에 새 기기가 나타나는지.
- 이미 등록됐던 기기 재등록: 기기 재플래시(NVS 초기화) 후 등록. §2-2 전까지는 이 방법뿐.
- 카메라: 앱 등록 불가. 플래시 시 등록된 카메라를 목록에서 그룹 배정만.
- 서버 확인은 이쪽에서: `journalctl -u terra-api | grep devices/pair` 로 요청 도달·상태코드 확인.

## 4. 서버 참고 (변경 없음)

`/devices/pair`, `/cameras/pair`, `PATCH … enclosure_id`, `unlink`, `DELETE` 계약은 그대로입니다. 등록·할당·삭제 API 는 전부 있고, 빠진 것은 **기기 쪽 결과 통보와 재등록**뿐입니다.

## 5. 최종 BLE 계약 (사육장 기기 · 카메라 공통, 2026-09-17 펌웨어부터)

서비스/특성 UUID 는 기존과 동일(`…9abc` 서비스, TX `…9abd` Notify, RX `…9abe` Write). 기기 이름 접두어: 사육장 `terra-iot-`, 카메라 `FB2_P4_CAM_`.

### 5.1 등록 시퀀스 (신규·삭제 후 재등록·다른 계정 기기 모두 동일)

```
UNPAIR            → UNPAIR_OK            (처음 등록하는 기기도 OK — 무해)
SSID:<ssid>       → SSID_OK
PASS:<pw>         → PASS_OK
NAME:<이름>        → NAME_OK
ENC:<enclosure_id>→ ENC_OK               (선택: 등록과 동시에 세트 배정. 생략 시 등록 뒤 PATCH)
JWT_BEGIN <len>   → JWT_BEGIN_OK         (len = JWT 전체 바이트 수, ≤ 2048)
JWT:<chunk> × N   → JWT_CHUNK a/b … 마지막에 JWT_OK <len>
CONNECT           → CONNECTING → WIFI_OK → PAIRING → PAIR_OK <id>   또는 PAIR_FAIL <reason>
```

- **BLE 광고는 항상 켜져 있지 않습니다 (2026-09-17 펌웨어부터).** 부팅 후 **3분간** 광고하고, WiFi 가 붙어 있는 동안은 광고를 끕니다 (BLE 와 WiFi 가 라디오를 나눠 써서 2~3분마다 WiFi 가 20~30초씩 끊기던 문제의 수정). WiFi 가 60초 이상 끊기면 다시 광고합니다. 따라서 **이미 동작 중인 기기를 재등록할 때는 기기 전원을 다시 켜고 3분 안에 연결**해야 합니다. 스캔에 안 잡히면 이 안내를 띄워 주세요.
- 결과 알림(`PAIR_OK`/`PAIR_FAIL`) 약 0.5초 뒤 기기가 BLE 를 끊고, 위 규칙에 따라 다시 광고합니다(부팅 3분 이내면 계속 광고). 앱은 **`PAIR_OK` 의 id 로 성공 판정**(`GET /devices`·`/cameras` 폴링 불필요).
- 이미 다른 자격증명으로 동작 중이던 기기(삭제 후 재등록)는 `PAIR_OK` 뒤 스스로 재부팅해 새 자격증명으로 올라옵니다(약 20~30초 후 온라인).
- `WIFI_OK` 뒤 JWT 를 보내지 않은 경우: 이미 등록된 기기면 WiFi 만 바꾼 것으로 처리(기존 동작), 미등록 기기면 `PAIR_FAIL no_jwt`.

### 5.2 알림 전체

| 알림 | 의미 |
|---|---|
| `SSID_OK` `PASS_OK` `NAME_OK` `ENC_OK` | 값 저장 |
| `JWT_BEGIN_OK` / `ERR:JWT_BEGIN bad len N` / `ERR:JWT_ALLOC` | JWT 버퍼 준비 / 길이 범위 밖 / 메모리 부족 |
| `JWT_CHUNK <누적>/<전체>` → `JWT_OK <len>` | 청크 진행 → 완성 |
| `UNPAIR_OK` / `UNPAIR_FAIL` | 저장 자격증명 삭제 결과 |
| `CONNECTING` → `WIFI_OK` / `WIFI_FAIL` | WiFi 연결 |
| `PAIRING` | 서버 등록 진행 중(수 초) |
| `PAIR_OK <device_id \| camera_id>` | 등록 성공. 예 `PAIR_OK terra-a1b2c3d4`, `PAIR_OK p4cam-79b5d844` |
| `PAIR_FAIL <reason>` | `401` JWT 만료/무효 · `timeout` 서버 미도달 · `server_5xx` · `http_<n>` 그 외 HTTP 오류(예 `http_400` enclosure_id 권한 없음) · `no_name` · `no_jwt` · `no_time`(카메라: 시계 동기화 실패 **그리고** 서버 연결 실패 — 0.4.8 부터는 시계만 못 맞추면 등록을 진행하므로, 이 사유는 "이 WiFi 는 인터넷이 막혀 있음" 으로 안내) · `error` |
| `ERR:NO_SSID` `ERR:UNKNOWN_CMD` | 기존과 동일 |

### 5.3 앱이 바꿀 것

1. 등록 시퀀스 맨 앞에 `UNPAIR` 전송(§2-2). 삭제 화면은 그대로.
2. 성공 판정을 `PAIR_OK` 수신으로(§3 의 10초 폴링 우회 제거). `PAIR_FAIL` 은 reason 별 안내(401 → 재로그인, timeout → 기기 WiFi/인터넷, http_400 → 세트 권한).
3. 카메라도 같은 시퀀스로 등록 가능(`FB2_P4_CAM_` 스캔). 개발 계정 자동 등록은 폴백으로만 남음.
4. (선택) 세트 화면에서 등록할 때 `ENC:` 로 바로 배정.
