## 회신 양식

| 항목 | 회신 |
|---|---|
| ①-1 데이터 부족 날 일일 행 생성 여부 | **만들어진다.** 대상 기기마다 카드가 둘 다 `null` 이어도 행을 저장한다(늦어도 08:15 1차, 09:05 2차) |
| ①-2 일일 "모자람" 기준 | 그 지표가 **유효 수집일이 아님** = 그날(08:00~다음 날 08:00) 표본이 예정 28,800개의 80% 미만. 주간 `ERR_DISCONNECT`(유효일 3일 이상·누락률 50% 이상)와는 **기준이 다르다**(하루 단위라 주간 기준은 맞지 않음) |
| ①-3 1안(카드 자리) 수용 여부 | **수용.** `element` 는 `"temp"`/`"humid"`, `code: "ERR_DISCONNECT"`, `status: "caution"`(null 대신 — 기존 카드 타입을 넓히지 않으려고), `title`·`lines` 는 Figma `1736:5264` 원문. `data` 는 `{"events": [], "valid_day": false}` |
| ②-1 습기 미감지 판정 조건 | 이미 구현. 일일: 그날 습도 이벤트 0 + 습기 사이클 0 + 습도가 유효 수집일. 주간: 그 주 습도 이벤트 0 + 습기 사이클 0. 앱 짐작("습도가 올라간 일이 한 번도 없음, ①과 구분")과 같다 |
| ②-2 코드 이름 | `HUM_NO_MIST` (이미 사용 중) |
| ②-4 주간에서 카드를 대신하는지 | `notices` 가 아니라 **`humid_card` 자체**로 온다(`status: "caution"`). 그래서 다른 습도 카드와 같이 오는 일은 없다. `replacesCard` 는 고칠 필요 없음 |
| 배포 예정일 | ① 은 PR 머지·배포 후(배포는 이관훈님 일정). 배포 전 날짜의 행은 다시 만들지 않는다 |

## ① 일일 `ERR_DISCONNECT` 세부

```json
"temp_card": {
  "element": "temp", "code": "ERR_DISCONNECT", "status": "caution",
  "title": "데이터 수집이 원활하지 않았어요",
  "lines": ["일일 분석을 위한 데이터가 충분하지 않아요. 전원과 Wi-Fi 연결 상태를 확인해 주세요"],
  "data": {"events": [], "valid_day": false}
}
```

- **지표별 판정.** 온도·습도 둘 다 모자라면 두 카드 모두 안내다(앱 말대로 두 줄로 그려진다).
- **이벤트 카드가 먼저다.** 수집이 모자란 날이라도 그날 주의·경고 이벤트가 있으면 이벤트 카드만 온다(주간 Q4 r2 "이벤트 있으면 카드만"과 같은 방향).
- **등록 첫날은 내지 않는다.** 기기 등록 시각이 구간 시작(08:00)보다 늦으면 표본이 모자란 게 당연하다. 이 날까지 "Wi-Fi 확인해 주세요"를 띄우면 오안내라서 `null` 그대로 둔다. (요청서에는 없던 경우라 서버가 정했다. 다르게 원하면 알려 주세요.)
- **수집은 충분한데 카드가 없는 날은 그대로 `null`이다.** 습기 사이클 스위치가 꺼진 날의 습도, 습기는 있었는데 건기 도달이 0인 날 등이다.

## ②-4 앱에 부탁할 것 — 주간 "습기 미감지" 칩

Figma 주간 습도(`1738:5288`)는 "안내" 칩인데, 서버는 `HUM_NO_MIST` 를 일반 습도 카드(`status: "caution"`)로 보낸다. 지금대로면 앱은 "주의" 상태 칩을 그린다.

- **추천:** 앱이 `code == "HUM_NO_MIST"` 인 주간 카드만 상태 칩 대신 "안내" 칩으로 그린다.
- 서버가 이걸 `notices` 로 옮기지 않는 이유: 응답 모양이 바뀌어 이미 저장된 주간 행과 어긋나고, 일일·주간이 같은 코드를 같은 자리(습도 카드)에 두는 지금 구조가 깨진다.
- 일일 카드는 상태 칩이 없어서 할 일이 없다.
- 이 카드는 습기 사이클 스위치(`HUMID_CYCLES_ENABLED`)를 켠 뒤에만 나온다. 일일은 켠 다음 날부터, 주간은 켠 주 다음 주부터다. 화면에서 안 보이면 먼저 스위치 상태를 확인해 주세요.

## ③ 주간 문구

알았다. 서버 문구(`주간 데이터 수집이 원활하지 않았어요` / `센서 전원과 Wi-Fi 연결 상태를 확인해 주세요`)를 그대로 둔다. 확정되면 서버에서 한 줄만 바꾸면 된다. 다만 주간 행은 주 1회만 만들어서, 지난 주 행에는 옛 문구가 남는다. 소급이 필요하면 확정 문구와 함께 알려 주세요(일회성 재생성 스크립트로 처리).
