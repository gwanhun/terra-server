# 앱 요청 — 카메라 네트워크 신호 약함 안내 (`camera.weak_signal`)

> **대상**: 앱 담당
> **작성**: terra-server 백엔드, 2026-11-13
> **성격**: 새 안내 1종. 서버가 자동으로 넣고 자동으로 내립니다. 앱은 새 `kind` 하나를 초점 안내 막대 자리에 띄우면 됩니다.
> **서버 상태**: **구현 완료, 아직 꺼져 있음**(2026-11-14). 배포 뒤에도 스위치를 켜기 전까지는 행을 넣지 않습니다. 아래 3번 질문 답을 받은 뒤 계약을 확정하고 켭니다. 계획서: [specs/stage-v-camera-weak-signal-notice.md](../specs/stage-v-camera-weak-signal-notice.md).
> **참고**: 초점 안내 `camera.focus_needed`(카메라 단위, `focus_notice_providers.dart`)와 같은 테이블·같은 방식입니다. `kind` 만 다르고 `data.camera_id` 로 카메라를 가리키는 것도 같습니다.

## 1. 무엇을 하나

카메라 WiFi 신호가 약한 상태가 10분 넘게 이어지면, 그 카메라 화면 위 막대(초점 안내가 뜨는 자리)에 아래 문구를 띄웁니다.

> 네트워크 신호가 약하니 점검해 주세요

- 표시 위치는 **카메라 화면 위 막대 한 곳뿐**입니다. 푸시는 보내지 않습니다.
- 신호가 회복되면 서버가 읽음 처리해서 막대가 저절로 사라집니다.
- 사용자가 막대를 누르면 초점 안내와 같이 읽음 처리합니다.

| 항목 | 기준 |
|---|---|
| 발송 | 카메라 RSSI **−75dBm 이하가 10분 넘게** 이어질 때. 중간에 −74~−71 이 섞여도 이어진 것으로 보고, −70 이상이 오면 처음부터 다시 셉니다 |
| 해제 | **−70dBm 이상**으로 회복하면 서버가 `read_at` 을 채움 |
| 반복 제한 | 카메라 1대당 24시간에 1회. 안 읽은 안내가 남아 있으면 새로 넣지 않음 |
| 대상 | 카메라만 (사육장 기기는 제외) |

## 2. 계약(안) — `app_notifications` 행

서버가 `service_role` 로 직접 INSERT 합니다. 초점 안내와 같이 outbox(푸시)를 타지 않습니다.

| 컬럼 | 값 |
|---|---|
| `user_id` | `cameras.owner_id` |
| `kind` | `camera.weak_signal` |
| `category` | `camera` |
| `title` | `네트워크 신호가 약하니 점검해 주세요` |
| `body` | `공유기와 카메라 사이 거리나 장애물을 확인해 주세요` |
| `route` | `/crecam` |
| `source` | `external` |
| `source_event_id` | 새 uuid |
| `dedupe_key` | `net-weak:` + `cameras.id` + `:` + 같은 uuid |
| `data` | `{"kind":"camera.weak_signal","source":"external","camera_id":"<cameras.id uuid>","rssi":-78}` |
| `read_at` | NULL 로 넣음. 회복 시 서버가, 누르면 앱이 채움 |

초점 안내와 다른 점은 하나입니다. **서버도 `read_at` 을 채웁니다**(신호 회복 시). 안 읽은 행 목록을 구독하는 지금 구조라면 막대가 저절로 내려갈 것으로 봅니다.

`data.camera_id` 에는 `cameras.id`(uuid)를 넣습니다.

## 3. 확인 부탁드리는 것

1. **알림함 노출**: `app_notifications` 에 넣으면 알림함에도 1건 보일 텐데, 이번 안내는 막대에만 보여야 합니다. 이 `kind` 를 알림함 목록에서 빼 주실 수 있나요? 어렵다면 다른 방법을 제안해 주세요.
2. **기존 화면 안내와의 관계**: 9/28 합의로 앱이 −75 이하 약 1분 연속이면 설치 위치 안내를 직접 띄우고 있습니다(`docs/APP_DEVICE_REBOOT_SYS_STATE_2026-09-28.md`). 같은 카메라 화면에서 새 막대와 겹치는지, 겹치면 어느 쪽을 남길지 알려 주세요.
3. **서버 측 읽음 처리**: 서버가 `read_at` 을 채웠을 때 막대가 내려가는지 확인 부탁드립니다. 서버 켜기 전에 테스트 계정에 행을 직접 넣고 `read_at` 을 채워서 같이 확인하려 합니다.
4. **`body`·`route`**: `body` 는 NOT NULL 이라 위 문구를 넣습니다. 막대에 `title` 만 쓴다면 `body` 문구는 앱 의견을 따르겠습니다. `route` 는 초점 안내와 같은 `/crecam` 으로 뒀습니다.
5. **구버전**: 이 `kind` 를 모르는 앱 버전에서는 알림함에 "일반 알림"으로만 보일 것으로 봅니다. 맞는지 확인 부탁드립니다.
6. **막대 우선순위**: 같은 카메라에 초점 안내와 신호 안내가 동시에 안 읽음이면 어느 쪽을 먼저 보일지는 앱에서 정해 주세요.

## 4. 일정

1. 서버 배포(스위치 꺼짐) 뒤 2~3일간 "보냈을 대상" 로그만 봅니다. 이 기간에는 행이 들어가지 않습니다.
2. 그 사이 테스트 계정에 위 계약 행을 직접 1건 넣어 드리겠습니다. 막대가 그 카메라에만 뜨는지, `read_at` 을 채우면 내려가는지 같이 확인 부탁드립니다. 넣을 계정과 카메라를 알려 주세요.
3. 3번 질문 답과 앱 수신부 준비가 끝났다고 알려 주시면 그때 실제 발송을 켭니다.
