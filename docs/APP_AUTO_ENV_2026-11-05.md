## 1. 동작 규칙 (화면 설명 문구에 참고)

| 상황 | 서버 동작 |
|---|---|
| 습도 > MAX **1시간 연속** | 환기팬 켬. v4 과습 주의 알림과 같은 조건(Figma 메모 "습도 {Max}% 초과 1시간 이상 유지") — 분무 직후 잠깐 높은 습도로는 켜지지 않음 |
| 온도 > MAX **3분 연속** | 환기팬 켬 |
| 종료 | 켜게 만든 원인이 모두 아래 종료선 이하로 **1분 연속**이면 끔 |
| ・습도 종료선 | MAX − 5%p. 단 MIN·MAX 가 가까우면 두 값의 가운데(예: 75~80% → 77.5%) |
| ・온도 종료선 | MAX − 0.5℃ |
| 추운 날 | 온도 ≤ 온도 MIN 이면 **습도 때문에는 환기하지 않음**(돌고 있으면 끔). 고온 원인은 해당 없음 |
| 다시 켜기 | 자동 환기가 끝난 뒤 **10분**은 다시 켜지 않음 |
| 하루 상한 | 자동 환기는 하루(KST 0시 기준) **총 12시간**까지. 넘으면 끄고 그날은 다시 켜지 않음 |
| 팬 1회 | `fan_on` + `duration_ms: 3600000`(1시간). 원인이 계속되면 1시간 타이머가 끝난 직후 다시 켬(몇 초 꺼졌다 켜짐) |
| 습도 < MIN **3분 연속** | 3초 분무 **1회** |
| 다시 분무 | 습도가 MIN 이상으로 **회복된 뒤** 다시 내려가야 함 + 직전 분무(수동·예약·자동 모두)와 **2시간** 간격 + 자동 분무 **하루 4회**까지 |
| 팬이 켜져 있을 때 | 자동 분무 보류. 팬이 꺼지면 다시 판정 |
| 사용자가 팬을 끔 | **30분** 동안 자동 환기 안 함 |
| 사용자가 팬을 켬 | 자동이 끄지 않음. 자동은 자기가 켠 팬만 끔 |
| 센서 오류·값 없음·오프라인 | 판정 안 함(추정해서 켜지 않음) |

기준값은 설정 화면의 적정 온습도(`target_*`), 비어 있으면 기본값(온도 18~27℃, 습도 40~80%)입니다. 온도 보정이 켜져 있으면 보정된 온도를 씁니다.

## 2. 계약 (요청서 §4)

### C1 토글 저장

`GET/PATCH /devices/{id}/settings` 에 두 필드가 추가됩니다.

| 필드 | 타입 | 기본 |
|---|---|---|
| `auto_vent_enabled` | bool | `false` |
| `auto_mist_enabled` | bool | `false` |

- PATCH 는 `true`/`false` 만 받습니다. `null`·`"true"`(문자열)는 422.
- 두 필드만 보내도 됩니다(다른 값은 바뀌지 않음).
- 서버 반영은 **최대 60초** 늦을 수 있습니다(설정 캐시). 끈 직후 1분 안에 자동 명령이 하나 더 나갈 수 있습니다.

### C2 자동 명령 구분

`commands.source = 'auto'`, `issued_by` = 기기 소유자. 원인은 `commands.reason`:

| reason | 표시 예 |
|---|---|
| `auto_vent:humid_high` | 자동 환기 켜짐 (습도 높음) |
| `auto_vent:temp_high` | 자동 환기 켜짐 (온도 높음) |
| `auto_vent:humid_high+temp_high` | 자동 환기 켜짐 (온도·습도 높음) |
| `auto_vent_end` | 자동 환기 꺼짐 (적정 범위 도달) |
| `auto_vent_cold` | 자동 환기 꺼짐 (온도 낮음) |
| `auto_vent_cap` | 자동 환기 꺼짐 (하루 최대 시간) |
| `auto_vent_disabled` | 자동 환기 꺼짐 (자동 환기 끔) |
| `auto_mist` | 자동 분무 (습도 낮음) |

- 요청서의 `humid_high`/`temp_high`/`humid_low` 와 문자열이 다릅니다. 위 값을 써 주세요.
- 사용자 조작 직후라 쓸모없어진 대기 중 자동 명령은 `status='expired'`, `result='superseded'` 로 바뀝니다. 기록에서 숨기거나 "취소됨"으로 보여 주세요.
- 자동 명령은 푸시가 없고 실패 푸시도 없습니다.

### C3 지금 상태

`devices.auto_env_state` (jsonb, null = 아직 기록 없음). 바뀔 때만 갱신, `devices` Realtime 으로 받습니다.

```json
{
  "vent": {
    "active": true,
    "causes": ["humid_high"],
    "since": "2026-11-05T05:10:00+00:00",
    "paused_until": null,
    "schedule_hold": false,
    "last_end_at": "2026-11-05T03:40:00+00:00",
    "runtime_today_sec": 5400
  },
  "mist": {"last_at": "2026-11-05T02:00:00+00:00", "today_count": 1},
  "day": "2026-11-05",
  "updated_at": "2026-11-05T05:10:03+00:00"
}
```

| 키 | 뜻 |
|---|---|
| `vent.active` | 자동이 켠 팬이 지금 돌고 있음(기기 응답 확인 뒤 true) |
| `vent.causes` | `humid_high` / `temp_high` |
| `vent.paused_until` | 사용자 조작으로 자동 환기를 쉬는 끝 시각 |
| `vent.schedule_hold` | 구간 예약이 팬을 돌리는 중이라 자동이 쉬는 중 |
| `runtime_today_sec` | 오늘 **끝난** 자동 환기의 누적(12시간 = 43200 상한). 지금 돌고 있으면 화면에선 `now − vent.since` 를 더해 주세요(매 샘플 갱신을 막으려고 진행 중 시간은 안 넣음) |
| `vent.since` | 이번 자동 환기가 시작된 시각. 1시간마다 다시 켜도 그대로 |
| `mist.today_count` | 오늘 자동 분무 수(상한 4) |

앱은 **읽기만** 해 주세요. 써도 서버가 다음 변경 때 덮어씁니다.

### C4 지원 여부

별도 capability 키 없음. 텔레메트리에 `fan` 이 오는 기기는 자동 환기, `relay`(분무 펌프)가 오는 기기는 자동 분무 지원으로 보면 됩니다.

### C5 예약과의 관계

`source='auto'` 라 예약 목록·예약 마지막 실행 결과(`source='schedule'`)에 섞이지 않습니다.

## 3. 질문 답 (요청서 §6)

| # | 질문 | 답 |
|---|---|---|
| 1 | 서버 vs 펌웨어 | **서버 판정** + `duration_ms` 안전장치. 펌웨어 변경 없음. 섀도 모드로 먼저 검증합니다 |
| 2 | 초안 숫자 | 초안 그대로 확정하되, **습도 원인은 Figma 최신 메모대로 "MAX 초과 1시간 연속"**(초안의 "3분 연속 + 분무 직후 보호 60분" 대신 — 보호가 따로 필요 없음). 서버가 더한 안전값 4개: 종료 확인 1분, 자동 환기 끝난 뒤 10분 쉼, 하루 자동 환기 12시간 상한, 꺼진 팬 재명령 최소 5분 간격. 추운 날 습도 환기 금지, 습도 종료선 가운데값 하한도 추가(§1) |
| 3 | 고온 때 어느 팬 | **환기팬만**. 냉각팬(`fan2`)은 자동으로 안 켭니다 |
| 4 | 자동 분무 시간 | **고정 3초** |
| 5 | "예약 실행 중" 정의 | **구간 예약(켜기·끄기 짝)이 켜 둔 구간만**. 아래 참고 |
| 6 | 자동 작동 푸시 | **없음**. 물통 비움 의심 알림은 이번 범위 밖 |

§6-5 세부:
- 켜기·끄기 짝 예약이 **둘 다 켜져 있고**, 지금이 켜기~끄기 사이면 자동 환기가 쉽니다(`vent.schedule_hold = true`). 짝 중 한쪽만 켜진 예약, 단발 예약(타이머 켜기 포함), 가드로 건너뛴 회차는 "예약 실행 중"으로 보지 않습니다.
- 분무에는 구간 예약이 없어서, 서버 기준으로는 Figma "분무 · 예약 실행 중"(`1657:5361`) 상태가 생기지 않습니다. 자동 분무는 예약과 무관하게 동작합니다.
- 예약이 끝나 팬을 끈 뒤에도 원인이 남아 있으면 3분 뒤 자동 환기가 다시 켤 수 있습니다(의도된 동작).

## 4. 알려진 한계

- **자동 환기 중 사용자 타이머**: 자동이 켠 팬에는 펌웨어 1시간 타이머가 걸려 있어서, 그동안 사용자가 "1시간 켜기" 같은 타이머 칩을 누르면 기기가 **`busy` 로 거절합니다**(연장되지 않음, 펌웨어 소스 확인 2026-11-05). "잠시 후 다시 시도" 계열 문구를 권합니다. 먼저 끄고(`fan_off` 는 타이머도 취소) 다시 켜면 됩니다.
- **자동 환기 중 사용자 "켜기"**(타이머 없는 `fan_on`): 펌웨어가 자동 OFF 예약을 **취소하고 계속 켜 둡니다**(펌웨어 소스 확인 2026-11-05). 그때부터 사용자 팬이라 자동은 끄지 않습니다 — 사용자가 끌 때까지 켜져 있습니다.
- **명령이 거의 동시에 겹칠 때**: 서버는 자동 명령을 보내기 직전 취소 여부를 다시 확인해서, 사용자 조작으로 취소된 자동 명령은 보내지 않습니다. 다만 이미 기기로 나간 자동 명령과 사용자 명령이 수백 ms 안에 겹치면 순서가 보장되지 않습니다. 사용자 명령의 응답이 오면 그 뒤로는 자동이 따라갑니다.

## 5. 켜는 순서

1. DB 마이그레이션 → 서버 배포(스위치 꺼짐, 변화 없음)
2. 테스트 기기 섀도 모드 2~3일(명령 없음, 앱 영향 없음)
3. 테스트 기기 1대 실제 명령
4. 전체 켬 → 앱 토글 출시

각 단계마다 이 문서 맨 위 "배포 상태"를 갱신해 알려 드릴게요.

## 6. 추가 질문 답 (요청서 §7, 2026-11-05 저녁)

| # | 질문 | 답 |
|---|---|---|
| 1 | 습도 조건 1시간 연속으로? 분무 뒤 60분 보호는? | **바꿨습니다.** 습도 > MAX **1시간 연속**(v4 과습 주의와 같은 조건)이면 환기를 켭니다. 분무 뒤 60분 보호는 **없앴습니다** — 분무 직후 높은 습도는 보통 1시간 안에 내려가 따로 보호할 필요가 없습니다. 온도는 3분 그대로입니다(§1 표 갱신, PR #48 에 포함) |
| 2 | 자동 환기가 꺼진 기기에서도 `vent.schedule_hold` 를 계산하나? | **안 합니다.** 두 토글이 다 꺼진 기기는 서버가 예약·상태를 아예 보지 않아 `auto_env_state` 를 쓰지 않습니다(섀도 모드에서도 안 씀). Figma "예약 실행 중" 화면은 앱이 예약 목록으로 직접 판정해 주세요. 서버 기준: 같은 `pair_id` 의 `fan_on`·`fan_off` 두 행이 **둘 다 enabled** 이고, 지금 기준 마지막으로 실행된 쪽이 `fan_on` 이면 "예약 실행 중"(여러 짝이면 하나라도) |
| 3 | 앱 계정 기기 1대를 테스트 허용 목록에? | **가능합니다.** device_id(UUID)를 알려 주세요. 허용 목록(`AUTO_ENV_DEVICES`)은 서버 배포 담당이 바꿉니다. 섀도 기간에는 명령도 `auto_env_state` 도 나가지 않아 앱 화면엔 아무것도 보이지 않습니다 — 앱 실기 확인은 "1대 실제 명령" 단계부터입니다 |
| 4 | 1시간 타이머 끝난 뒤 재켜짐 `fan_on` 은 최대 몇 분 안에? | 보통 **타이머 만료 후 15초 안**(텔레메트리 꺼짐 2샘플 ≈ 6초 + 명령 발행 ≈ 1초). 그 재켜짐이 거절·무응답이면 5분 뒤 다시 판정해 **최대 약 6분**. 반면 자동 환기가 **끝난 뒤 새로 켜는 것은 항상 10분 이상** 뒤입니다. 그래서 "끝 + 10분 안이면 한 줄" 은 경계가 겹칩니다 — **끝 + 6~9분**으로 합쳐 주세요. 만료 시점에 원인이 풀려 있으면(습도·온도가 MAX 이하) 재켜짐 없이 그대로 끝납니다 |
| 5 | 자동 분무 명령 모양 | **맞습니다.** `action='mist'`, `payload = {"duration_ms": 3000}`, `source='auto'`, `reason='auto_mist'`. 기기 상한 때문에 나눠 보내더라도 DB 행 payload 는 3000 그대로입니다 |
