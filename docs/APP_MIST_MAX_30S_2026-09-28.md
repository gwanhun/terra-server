# 앱 전달 — 분무 상한 30초 펌웨어 + 20초 분무 개방: 10초는 분할 없이, 20초 칩 추가 가능

> **대상**: 앱 개발 담당
> **작성**: terra-server 백엔드 담당, 2026-09-28
> **성격**: 9/23 회신([BACKEND_HANDOFF_REPLY_MIST_DURATION_2026-09-23.md](BACKEND_HANDOFF_REPLY_MIST_DURATION_2026-09-23.md))에서 "보류"했던 **펌웨어 상한 상향**을 이번 리플래시에 포함했고, 서버 허용값에 **20000** 을 추가했습니다. 필수 작업은 없고, **20초 칩 추가는 선택**입니다.
> **관련 커밋**: 펌웨어 nano `a09772f` / supermini `7ed013d`. 서버: 허용값 20000(이번 커밋), 문서 `291930c`.

| # | 항목 | 앱에서 할 일 | 권장도 |
|:---:|---|---|:---:|
| ① | 신 펌웨어 기기는 10초 분무가 **1회 명령·10초 연속 분사** | 없음. 기존 5초·10초 칩 그대로 | — |
| ② | `commands` 에 `source='timer'` 후속 행이 **안 생김** (신 펌웨어 기기) | 이력 화면에서 후속 행 유무로 분기하는 코드가 있으면 확인 | 확인 |
| ③ | 버튼 잠금 시간 | **총 분사 시간 + 3초** 규칙 그대로 (10초 → 13초). 바꿀 필요 없음 | — |

## 1. 무엇이 바뀌었나

| | 구 펌웨어 (~9/28) | 신 펌웨어 (9/28+) |
|---|---|---|
| 펌웨어 분무 1회 상한 | 5초 (`MIST_MAX_MS 5000`) | **30초** |
| `capabilities.mist_max_ms` 보고 | 없음 → 서버가 5000 으로 간주 | **30000** — 페어링 body 와 3초 telemetry 양쪽에 실림. 재페어링 없이 첫 telemetry 에서 서버 DB 갱신 |
| 앱이 10초 분무 요청 시 | 서버가 5초 + 5초로 분할 (총 ~12초, 중간 2초 쉼) | **한 번에 10초** 연속 분사 |
| `commands` 행 | 원 명령 1 + 후속 `source='timer'` 1 | **원 명령 1 만** |
| 5초 분무 | 한 번에 | 한 번에 (변화 없음) |

- 30초는 서버 이상값·침수 방지용 펌웨어 최후 방어선이지, 앱이 30초를 보낼 수 있다는 뜻이 아닙니다(보내면 400).

### 1.1 허용값에 20000 추가 (서버, 2026-09-28)

`duration_ms` 허용값: **1000 / 2000 / 3000 / 5000 / 7000 / 10000 / 20000**. REST `POST /devices/{id}/mist`, `commands` 직접 INSERT, 예약(`POST /schedules`) 모두 같습니다.

| 기기 | 20초 요청 시 |
|---|---|
| 신 펌웨어 (`mist_max_ms` 30000) | **한 번에 20초** 연속 분사, `commands` 1행 |
| 구 펌웨어 (미보고 = 5000) | 5초 × 4 분할. 원 명령 1행 + `source='timer'` 후속 3행(15000 → 10000 → 5000 으로 발행 시마다 재분할). 총 약 26초, 물 양은 20초분 |

- 20초 칩을 넣을 경우 버튼 잠금은 기존 규칙(**총 분사 시간 + 3초**) 그대로 23초. 구 펌웨어 기기는 분할 사이 쉼 때문에 실제 26초 정도 걸리지만, 잠금 중 재요청은 펌웨어가 `busy` 로 거절하므로 문제 없습니다.
- 칩 노출을 기기별로 나눌 필요 없습니다. 어느 펌웨어든 서버가 알아서 처리합니다.
- 분할 로직은 서버에 그대로 남아 있습니다. 구 펌웨어 기기는 계속 분할되고, 기기별로 자동 판단됩니다. 리플래시 순서와 무관하게 앱 동작은 같습니다.

## 2. 앱에서 확인할 것 (선택)

1. 명령 이력이 `source='timer'` 후속 행의 존재를 전제로 하는 표시(예: "2회 분사")가 있다면, 신 펌웨어 기기에서는 1행만 오는 것이 정상입니다.
2. 버튼 잠금은 9/23 규칙(총 분사 시간 + 3초) 그대로 두면 됩니다. 신 펌웨어에서는 3초 여유가 조금 남지만 문제 없습니다.
3. 예약(schedule)의 10초 분무도 동일하게 한 번에 나갑니다.
