# 앱 전달 — 라이브 시청 제한 (15분 · 5분 쉼 · 한 기기) — 2026-09-30

> 서버 PR: gwanhun/terra-server (feat/live-view-limit) · 설계: [`specs/live-view-limit.md`](../specs/live-view-limit.md)
> 기존 계약: [`APP_WEBRTC.md`](APP_WEBRTC.md) — 아래는 **추가/변경분만**.

## 한 줄
라이브는 **한 번에 15분**, 끝나면 **5분 쉼**, **한 번에 한 기기**만. 서버가 강제하고, 앱은 안내 화면과 "가져오기"만 구현하면 된다.

## 1. `POST /cameras/{id}/webrtc/offer` 요청 필드 추가

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `viewer_id` | string (≤64) | 권장 | **앱 설치별 고정 ID.** 처음 실행 때 UUID 생성 → 로컬 저장 → 매번 같은 값. 한 기기 판정에 쓴다 |
| `viewer_label` | string (≤64) | 권장 | 다른 기기에 보여줄 이름. **기기 종류 + 모델**, 예: `"iPhone 15"`, `"Galaxy S24"`, `"웹"` (서버는 40자로 자름) |
| `takeover` | bool | - | 기본 false. 사용자가 "연결할까요?"에 **예**를 누른 뒤 다시 보낼 때만 true |

`viewer_id` 를 안 보내면(구버전) 한 기기 제한 없이 15분·5분 쉼만 적용된다.

## 2. 응답

| 코드 | body | 앱 동작 |
|---|---|---|
| 200 | 기존 + `live_until` (ISO8601 UTC) | 영상 표시. `live_until` 로 남은 시간 표시 가능(선택) |
| **409** | `{"detail": {"code": "live_in_use", "viewer": "iPhone 15", "since": "<ISO>"}}` | **"iPhone 15에서 시청 중입니다. 연결할까요?"** [예/아니오]. 예 → 같은 요청에 `takeover: true`. 아니오 → 아무 요청 안 함 |
| **429** | `{"detail": {"code": "live_cooldown", "retry_after": 240}}` + 헤더 `Retry-After: 240` | **"녹화 진행을 위해 카메라 라이브가 절전모드로 들어갑니다"** + `retry_after` 초 카운트다운 후 다시 보기 버튼 활성. **자동 재시도 금지** |
| 429 | `{"detail": {"code": "rate_limited", "retry_after": N}}` | 시간당 연결 시도 과다(재연결 루프 안전망). 자동 재연결 중단, N초 뒤 버튼 |
| 502/504 | 기존 | 기존과 동일(백오프는 APP_WEBRTC §7.1) |

## 3. 보는 중에 끊기는 경우 — cameras Realtime

보는 중인 기기는 `cameras` 행 Realtime UPDATE 를 보고 판단한다(이미 구독 중인 채널).

| 조건 | 의미 | 화면 |
|---|---|---|
| `live_session_id` 가 **내 session_id 가 아닌 값**, `live_end_reason = "taken_over"` | 다른 기기가 가져감 | **"{live_viewer}에서 시청을 시작해 라이브가 종료됐어요"** + 다시 보기 버튼(누르면 409 → 가져오기 흐름) |
| `live_session_id = null`, `live_end_reason = "time_limit"` | 15분 끝 | **"녹화 진행을 위해 카메라 라이브가 절전모드로 들어갑니다"** + `live_cooldown_until` 까지 카운트다운 |
| `live_session_id = null`, 그 외 | 닫힘/실패 | 기존 종료 처리 |

⚠️ **위 세 경우 모두 자동 재연결 금지.** 가져오기 당한 쪽이 자동 재연결하면 두 기기가 서로 뺏는 루프가 된다
(09-29 재연결 루프로 카메라가 재부팅된 것과 같은 구조). 사용자가 버튼을 눌렀을 때만 다시 요청.

서버도 15분이 되면 카메라 세션을 직접 닫으므로, Realtime 을 못 받아도 영상은 멈춘다(peer connection `failed`/`disconnected`).
그때도 자동 재연결 대신 위 안내로.

## 4. 15분 시계 규칙 (알아둘 것)
- 15분은 **카메라 기준 연속 시청 시간**이다. 가져오기로 기기가 바뀌어도, 닫고 60초 안에 다시 열어도 시계가 이어진다.
  → 가져온 쪽은 남은 시간만 볼 수 있다(`live_until` 로 표시 권장).
- 사용자가 직접 닫았거나 가져오기 당한 경우는 5분 쉼이 없다. 쉼은 15분을 다 채웠을 때만.

## 5. 문구 (owner 결정, 필요 시 조정)
- 15분 종료: "녹화 진행을 위해 카메라 라이브가 절전모드로 들어갑니다"
  - 참고: 실제로는 카메라가 절전하지 않고 **라이브만 멈추고 녹화는 계속**한다. "녹화를 계속하기 위해 라이브를 잠시 멈췄어요"도 후보.
- 다른 기기 시청 중: "{viewer}에서 시청 중입니다. 연결할까요?"
- 가져오기 당함: "{viewer}에서 시청을 시작해 라이브가 종료됐어요"
